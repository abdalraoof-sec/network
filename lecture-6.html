②طرق تخصيص عناوين IP وبروتوكول DHCP

  • التخصيص الثابت (Static): إدخال الـ IP والقناع يدوياً؛ لتعيين عنوان لمنفذ راوتر Cisco نستخدم:
    interface FastEthernet 0/0
ip address 10.0.0.2 255.255.255.0
  • التخصيص الديناميكي عبر DHCP (المعيار RFC 2131):
    • يعمل بنمط Client-Server فوق بروتوكول UDP عبر المنفذ 67 للسيرفر والمنفذ 68 للمستخدم.
    • يزود الجهاز من مجمع العناوين (Pool) بـ 5 إعدادات: IP Address، Network Mask، Default Gateway، DNS Server Address، و Domain Name.
    • المراحل الأربعة الأساسية لتخصيص العنوان (DORA) وباقي رسائل DHCP:
      1. DHCPDISCOVERY: يرسلها العميل كـ Broadcast (255.255.255.255) ومن عنوان مصدر 0.0.0.0 للبحث عن سيرفر DHCP.
      2. DHCPOFFER: يرد بها السيرفر متضمنةً العنوان المقترح (YIADDR)، قناع الشبكة، وعنوان السيرفر (SIADDR / Server ID).
      3. DHCPREQUEST: يرسلها العميل كـ Broadcast (وليس Unicast) لتأكيد اختيار عرض سيرفر محدد (SIADDR) ولإعلام بقية سيرفرات DHCP بأن عروضها لم تُختر.
      4. DHCPACK: يرسلها السيرفر المختار لتأكيد منح العنوان والإعدادات.
      • رسائل إضافية مهمة: DHCPNACK (من السيرفر إذا لم يعد العنوان المقترح متاحاً)، DHCPDECLINE (من العميل للسيرفر إذا اكتشف أن العنوان مستخدم)، DHCPRELEASE (من العميل لتحرير العنوان عند إنهاء الاتصال)، DHCPINFORM (من العميل لطلب إعدادات إضافية بعد حصوله على IP).
    • DHCP Relay / Helper: إذا كان سيرفر DHCP في شبكة فرعية أخرى، يُضبط الراوتر كـ DHCP Relay ليلتقط رسائل البث (DHCPDISCOVERY و DHCPREQUEST) ويحولها للسيرفر البعيد ويعيد الرد للعميل.

③بروتوكول ARP والتوجيه بين الشبكات الفرعية (Inter-subnet Routing)

  • بروتوكول ARP (Address Resolution Protocol): يُستخدم لمعرفة عنوان MAC المقابل لعنوان IP معروف ضمن نفس الشبكة الفرعية:
    • ARP Request: يُرسل كـ Broadcast في الطبقة الثانية (يتضمن IP & MAC المرسل + IP الهدف فقط).
    • ARP Reply: يرد به الجهاز الهدف كـ Unicast (يتضمن IP & MAC الهدف)، ويُحفظ في جدول ARP Table (ARP Cache).
  • قواعد التوجيه بين الشبكات الفرعية (Inter-subnet Routing):
    • إذا كان الهدف في نفس الـ Subnet: يطلب المرسل MAC الهدف عبر ARP ويرسل الحزمة مباشرة.
    • إذا كان الهدف في Subnet مختلفة: يرسل الجهاز الحزمة إلى الـ Default Gateway (يطلب MAC منفذ الراوتر عبر ARP)، ثم يوجهها الراوتر بناءً على جدول التوجيه (Directly Connected أو Next-Hop أو المسار الافتراضي 0.0.0.0/0). Notice أن عناوين الـ Source/Destination IP تبقى ثابتة على طول المسار (إلا في حال وجود NAT)، بينما تتغير عناوين الـ MAC في كل قفزة.

④بروتوكولات وخوارزميات التوجيه (IP Routing Protocols)

  • مصادر بناء جدول التوجيه: الشبكات المتصلة مباشرة (Directly Connected)، المسارات الثابتة اليدوية (Static Routes)، والمسارات الديناميكية (Dynamic Routes).
  • التصنيف الأول (حسب نطاق العمل والأنظمة المستقلة AS - Autonomous System):
    • بروتوكولات داخلية (IGPs - Interior Gateway Protocols): تعمل داخل حدود الشركة أو النظام المستقل الواحد (AS)، ومنها: RIPv2، OSPF، EIGRP، IS-IS.
    • بروتوكولات خارجية (EGPs - Exterior Gateway Protocols): تعمل بين مزودات الخدمة أو الأنظمة المستقلة المختلفة (لكل منها رقم ASN)، وأشهرها BGP (BGP-4).
  • التصنيف الثاني (حسب الخوارزمية المعتمدة في IGPs):
الخوارزمية البروتوكول الأشهر مبدأ العمل والمعيار (Metric) المزايا والعيوب الجوهرية للامتحان
Distance Vector (DV) RIPv2 يتبادل جدول التوجيه كاملاً بشكل دوري مع الجيران فقط، ويعتمد عدد القفزات (Hop Count) ككلفة. عيوبه: لا يراعي عرض الحزمة (Bandwidth)، لا يملك رؤية كاملة للشبكة، يستهلك عرض الحزمة بالتحديثات الكاملة الدورية، ومعرض لحلقات التوجيه وبطء التقارب.
Advanced Distance Vector (Hybrid) EIGRP يكتشف الجيران برسائل ترحيب، يرسل الجدول كاملاً لأول مرة فقط ثم يرسل تحديثات جزئية عند التغيير فقط. يعتمد على عرض الحزمة (Bandwidth) والتأخير (Delay) بدل عدد القفزات، سريع التقارب، ومحصن ضد الحلقات.
Link-State OSPF يرسل كل راوتر إعلانات حالة الوصلة (LSA) عبر LSA Flooding لبناء قاعدة بيانات موحدة (LSDB) لكامل الشبكة، ثم يحسب أقصر مسار بخوارزمية SPF. يملك كل راوتر تصوراً كاملاً لبنية الشبكة، يعتمد الكلفة (Cost) بناءً على عرض الحزمة، ولا يرسل تحديثات إلا عند حصول تغيير في الوصلات.

⑤بروتوكول رسائل التحكم في الإنترنت (ICMP)

  • يُغلف مباشرة داخل IP Payload، وتكون قيمة حقل Protocol في ترويسة IPv4 تساوي 1.
  • جدول أنواع وأكواد رسائل ICMP الأساسية (مهم جداً للامتحان):
النوع (Type) الكود (Code) الوصف والاستخدام (Description)
0 – Echo Reply 0 رد لتأكيد إمكانية الوصول في أداة Ping.
3 – Destination Unreachable 0 الشبكة غير قابلة للوصول (Network unreachable - لا يوجد مسار في الراوتر).
3 – Destination Unreachable 1 الجهاز الهدف غير قابل للوصول (Host unreachable).
3 – Destination Unreachable 2 البروتوكول غير قابل للوصول (Protocol unreachable).
3 – Destination Unreachable 3 المنفذ غير قابل للوصول (Port unreachable).
3 – Destination Unreachable 4 التجزئة مطلوبة وعلم عدم التجزئة مضبوط (Fragmentation required, and DF flag set).
8 – Echo Request 0 طلب فحص الاتصال المرسل بواسطة أداة Ping.
11 – Time Exceeded 0 انتهاء قيمة TTL أثناء النقل (TTL Exceed in transit).
11 – Time Exceeded 1 انتهاء وقت إعادة تجميع الأجزاء المقسمة (Fragment reassembly time exceeded).
